## Architecture

**One Worker serves everything.** Hono handles `/api/*`; every other path falls through to Workers
Static Assets (`not_found_handling: single-page-application`) serving the built SPA. `vite dev` via
`@cloudflare/vite-plugin` runs that same Worker with local D1/R2, so dev behaves like production.

Single npm package, three TypeScript project references (`tsconfig.app.json` / `.worker.json` /
`.node.json`). Separation is enforced by directory + tsconfig boundaries, not workspaces — the
Cloudflare Vite plugin builds both halves from one Vite graph.

- **`worker/`** — Hono API: `routes/`, `middleware/`, `lib/`, `db/`.
- **`shared/`** — Zod schemas + inferred DTO types imported by *both* sides. Request payloads are
  validated server-side with `zValidator('json', schema)` using these same schemas, so client and
  server agree by construction. Change a payload shape here, never in one half only.
- **`src/`** — React SPA. React Router is used **as a library** (`createBrowserRouter` +
  `RouterProvider`) — no SSR, no framework mode, no loaders. TanStack Query owns all server state;
  Zustand owns the two client-only stores (auth token, UI prefs).
- **`migrations/`** — generated by drizzle-kit from `worker/db/schema.ts` and applied with
  `wrangler d1 migrations apply`. Change the Drizzle schema and regenerate; don't hand-edit
  generated SQL.

Ids are `crypto.randomUUID()` strings; timestamps are integer epoch ms.

### Auth model

Three credentials with distinct jobs — do not blur them:

| Thing | Lifetime | Carried in | Accepted by |
| --- | --- | --- | --- |
| Access JWT (HS256) | 15 min | memory only, `Authorization: Bearer` | every mutating route |
| `mdn_rt` refresh | 30 d | HttpOnly cookie, `SameSite=Strict`, path `/api/auth` | `/api/auth/refresh` only — single-use, rotated, stored as SHA-256 in `sessions` |
| `mdn_at` asset cookie | 30 min | HttpOnly cookie, `SameSite=Lax`, path `/api/projects` | asset **GET**s only |

`mdn_at` exists solely because `<img>`/`<object>` cannot send an `Authorization` header. Keeping it
off every mutating route is what makes the design CSRF-safe by construction — never accept it on a
POST/PATCH/DELETE.

`src/lib/api-client.ts` handles 401 → refresh → replay through a **single de-duplicated in-flight
refresh promise**: refresh tokens are single-use, so parallel rotations would invalidate each other.
The access token is never persisted; a reload re-bootstraps from the refresh cookie, which is why
`<RequireAuth>` awaits that bootstrap before rendering (no login flash).

Guests are real `users` rows with `is_guest = 1`. `POST /api/auth/upgrade` mutates that row in
place, so projects/documents/assets carry over with no migration.

Ownership is enforced server-side by `requireOwnership(projectId)` (joins on `user_id`). A foreign
row and a missing row both return **404, never 403** — a 403 would confirm the id exists. Keep that.

Password hashing is PBKDF2-SHA256 via Web Crypto (bcrypt/argon2 cannot run on Workers), stored as
`pbkdf2$sha256$<iters>$<salt_b64>$<hash_b64>` with constant-time comparison.

### Assets

R2 keys are `p/{projectId}/{assetId}/{filename}`. Uploads are validated in order: size ≤
`MAX_UPLOAD_BYTES`, declared MIME in `ALLOWED_MIME`, then a **magic-byte sniff of the first 8 bytes**
to confirm the declared type. SVG is rejected deliberately (XSS vector). Filenames are slugified and
de-duplicated per project (`report.pdf` → `report-1.pdf`); the stored `filename` is what markdown
references, under `UNIQUE(project_id, filename)`.

Asset references in markdown are a **flat per-project namespace matched on basename**.
`makeUrlTransform(projectId)` in `src/lib/markdown.ts` rewrites anything that isn't an absolute
`http(s):`/`mailto:`/`data:image/` URL to `/api/projects/{projectId}/assets/by-name/{name}`, so
`![](diagram.png)`, `![](./img/diagram.png)` and `[spec](spec.pdf)` all resolve to the same asset.
**The client-side normalization and the server-side one must stay behaviourally identical** — they
are mirrored on purpose, and a divergence silently breaks image resolution.

### Markdown pipeline

```
remarkPlugins: [remarkGfm, remarkMath]
rehypePlugins: [ [rehypeSanitize, schema], rehypeKatex, rehypeHighlight ]
urlTransform:  makeUrlTransform(projectId)
```

Order is deliberate: **sanitize first**, then let KaTeX and highlight.js emit their trusted markup
from already-clean text. Sanitizing afterwards would strip KaTeX's spans — the classic bug here. The
custom schema therefore has to preserve `math-inline`/`math-display` on `span`/`div` and
`language-*` on `code`. Raw HTML is never rendered.

Mermaid is intercepted via a `components.code` override and **dynamically imported** (~500 KB out of
the main bundle), rendered in an effect keyed on the code string. Parse errors must render an inline
error card rather than throw — the live preview re-renders on every keystroke while a diagram is
half-typed.

### Editor

Edit mode is a resizable split (CodeMirror ⇄ preview) whose collapse state lives in the Zustand
UI store and persists to localStorage. Autosave is a debounced `PATCH /documents/:id` carrying the
last-known `updatedAt` for optimistic concurrency (409 → "changed elsewhere" toast), plus explicit
⌘/Ctrl-S. Preview input is debounced through `useDeferredValue` so typing stays smooth.

## Constraints worth knowing

- **Version pin.** `rehype-katex@7` and `mermaid@11` both want `katex@^0.16`. Install
  `katex@^0.16.45`; `katex@0.18` breaks both.
- **CPU budget.** The Workers Free plan caps CPU at 10 ms/request, and PBKDF2 at 100 k iterations
  will blow it. `PBKDF2_ITERATIONS` is an env var precisely so this is a config change, not a code
  change — measure the real cost in the Phase 3 auth tests and set it from there. `verifyPassword`
  reads the count out of each stored hash, so changing it never locks an existing user out. Guest
  login does no hashing and is unaffected.
- **SPA and API must share an origin.** The cookies are first-party and host-scoped; splitting the
  API onto another host breaks auth.
- **D1's FK cascade never touches R2.** Project/asset deletion has to list and purge bucket objects
  explicitly (`worker/lib/r2.ts`) — the rows cascading away will not do it.
- The `by-name` route should 404 with a placeholder image for unknown names, so a broken markdown
  reference doesn't look like an app error.
- `worker-configuration.d.ts` is generated by `wrangler types` and gitignored.
